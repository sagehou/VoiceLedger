# Allow users to send a saved track for external transcription

The product owner requested direct access to external models, including a custom Base URL. Sessions on Windows and Android offer on-demand transcription of one committed track through OpenAI, Groq, SiliconFlow or a user-configured OpenAI-compatible `/audio/transcriptions` endpoint. The send dialog shows the service address and an audio disclosure. The **Send audio for transcription** action starts the job for that selection. The user supplies the audio language and can edit the preset model ID. [OpenAI audio reference](https://platform.openai.com/docs/api-reference/audio/createTranscription) · [Groq speech to text](https://console.groq.com/docs/speech-to-text) · [SiliconFlow audio reference](https://docs.siliconflow.com/en/api-reference/audio/create-audio-transcriptions)

The apps call the provider directly over HTTPS. Custom HTTP is limited to loopback. Requests carry one locally detected speech segment as mono PCM WAV plus the selected model and any required authorization. The worker bounds request size and duration and declines redirects. Provider calls run on the speech worker for saved sessions while capture is idle. Local transcription, capture and encrypted sync have their own entry points. API keys are held in memory for the current job and go to the worker over private Android IPC or Windows standard input. Error codes summarize provider failures without recording provider response bodies.

The existing journal stores final text with the track, audio spans and model provenance. A rerun can save a draft for review while preserving the selected revision. Users can edit and save that draft as a manual revision. The shared queue resumes from committed progress when the user sends again with the same service, model and language. A request interrupted after the provider receives its audio can be sent again during a retry.

Existing recordings and revisions require no migration. For external revisions, `ModelRef.runtime_version` identifies the endpoint protocol, `model_version` records provider management and `sha256` fingerprints the provider, endpoint and model configuration. The fingerprint excludes credentials. Local revisions continue to use the model artifact checksum. Rollback removes the external action and its clients. Existing external revisions remain readable as ordinary transcript records.
