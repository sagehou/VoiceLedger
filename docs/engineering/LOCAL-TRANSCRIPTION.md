# Local transcription

Download Whisper Tiny multilingual in **Models**. On the recording screen, enable **Live transcription**, choose **Auto**, Chinese, English or Japanese, then start recording. Auto detects the language per speech window. Recording-only is the default. The same models screen can transcribe saved audio. [Issue #10](https://github.com/sagehou/VoiceLedger/issues/10)

The worker reads committed Opus segments while the recorder is running. Both clients currently aim to seal about two seconds of PCM per segment. Partials appear separately from saved lines, and the preview shows the latest eight finals. On Windows, each line keeps its microphone or System loopback label. Android binds the isolated worker from the microphone service so processing continues when the activity leaves the foreground. Stop releases capture after the writer has sealed the tail, and speech can finish draining independently. If a worker is suspended or interrupted, choose the same model and language in Sessions to resume from each track's durable progress.

The app refreshes the device profile before starting a task. The shared installer checks the memory and storage reserves, resumes partial HTTPS downloads and verifies the pinned SHA-256 and size of every artifact before probing runtime loadability. Only verified models become available for transcription. Whisper Tiny uses the upstream family estimate at this stage. SenseVoice stays blocked in the app until its memory requirement is established. [Catalog](MODEL-CATALOG.md)

The Windows worker process and Android private speech service run inference at reduced priority. One worker per local profile can load a model. A read-only SQLite connection retrieves one committed Opus chunk at a time and validates its checksum. The recorder keeps its separate writer. WebRTC VAD receives transient 16 kHz mono frames. A change of track, source epoch or continuity ends the current speech window. Windows Mic and System loopback keep separate results and share the same loaded model.

Each speech window reuses one utterance ID for ephemeral updates. Only final text enters the local transcript database. Final revisions carry the track, session-relative range, contributing chunk spans, language and model version, runtime version and weight digest. Retrying the same model and language keeps the existing final. A different run for the same range can add a revision and leaves the selected revision in place. Windows sends partials through a same-user pipe and Android uses a private bound service.

GitHub Actions builds both pinned native engines, checks version and missing-model behavior on hosted desktops, and packages the Windows x64 and Android arm64 adapters. Model-free checks cover the VAD and transcript paths, the worker boundaries and the packaged manifest. Physical inference, language and mixed-language accuracy, RTF, RAM, and capture under model failure or pressure are **BLOCKED** until the #18 device campaign. [Issue #18](https://github.com/sagehou/VoiceLedger/issues/18)

The Auto regression builds the packaged Whisper adapter and runs pinned multilingual Q5_1 weights with the runner disconnected from the network. Its six synthetic utterances cover Mandarin Chinese, English and Japanese. Kokoro INT8 supplies Mandarin, eSpeak NG supplies English, and Open JTalk supplies Japanese. The report includes each detected language, its transcript, latency and the fixture SHA-256. Physical language accuracy and mixed-language results are tracked in #18. [Issue #10](https://github.com/sagehou/VoiceLedger/issues/10)


The hosted live test uses those same packaged adapters and pinned model files on the shared ABI with the network disconnected. It checks final text while capture is active, English-only translation, loopback track attribution, final audio drain, and resumption after a low-memory event. Screen-off capture, WASAPI contention, real-time latency, and real-device accuracy remain **BLOCKED** in #18.
