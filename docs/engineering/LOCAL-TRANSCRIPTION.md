# Local transcription

Download Whisper Tiny multilingual or SenseVoice Small in **Models**. On Android, enable **Live transcription**, choose the installed model and language, then start recording. Windows live transcription uses Whisper Tiny. Auto detects Mandarin, English and Japanese per speech window. Recording-only is the default. The same models screen can transcribe saved audio. [Issue #10](https://github.com/sagehou/VoiceLedger/issues/10)

The worker reads committed Opus segments while the recorder is running. Both clients aim to seal about two seconds of PCM per segment. The worker finalizes complete speech windows before previewing the unfinished window. With sufficient speech and resources, the first committed segment can yield text. Partials appear separately from the latest eight saved lines. On Windows, each line keeps its microphone or System loopback label. Android binds the isolated worker from the microphone service and shows when it is finishing transcription after Stop. If a worker is suspended or interrupted, choose the same model and language in Sessions to resume from each track's durable progress.

The app refreshes the device profile before starting a task. The shared installer checks the memory and storage reserves, resumes partial HTTPS downloads and verifies the pinned SHA-256 and size of every artifact before probing runtime loadability. Whisper Tiny uses the upstream family memory estimate. SenseVoice uses a provisional 1.1 GB peak RAM estimate based on the Android speech worker measurement. [Catalog](MODEL-CATALOG.md)

The Windows worker process and Android private speech service run inference at reduced priority. One worker per local profile can load a model. A read-only SQLite connection retrieves one committed Opus chunk at a time and validates its checksum. The recorder keeps its separate writer. WebRTC VAD receives transient 16 kHz mono frames. A change of track, source epoch or continuity ends the current speech window. Windows Mic and System loopback keep separate results and share the same loaded model.

Each speech window reuses one utterance ID for ephemeral updates. Only final text enters the local transcript database. Final revisions carry the track, session-relative range, contributing chunk spans, language and model version, runtime version and weight digest. Retrying the same model and language keeps the existing final. A different run for the same range can add a revision and leaves the selected revision in place. Windows sends partials through a same-user pipe and Android uses a private bound service.

GitHub Actions builds both pinned native engines, checks version and missing-model behavior on hosted desktops, and packages the Windows x64 and Android arm64 adapters. Model-free checks cover the VAD and transcript paths, the worker boundaries and the packaged manifest. Physical inference, language and mixed-language accuracy, RTF, RAM, and capture under model failure or pressure are **BLOCKED** until the #18 device campaign. [Issue #18](https://github.com/sagehou/VoiceLedger/issues/18)

The Auto regression runs both packaged adapters with pinned weights and the runner disconnected from the network. Kokoro INT8, eSpeak NG and Open JTalk generate two utterances each in Mandarin, English and Japanese. The reports include each detected language, CER or WER, inference latency, RTF, cold load time, process peak RSS and fixture SHA-256. SenseVoice produced fewer Mandarin and Japanese errors in the comparison. Whisper produced fewer English errors. Shortening Whisper's encoder context increased Japanese CER on this corpus, so the packaged decoder retains its existing settings. [Comparison](https://github.com/sagehou/VoiceLedger/actions/runs/45725041896)


The hosted live test checks final text while capture is active, English-only translation, loopback track attribution, final audio drain, and resumption after a low-memory event. The API 35 emulator installs the Android ARM64 APK and verifies both model downloads with ARM64 translation and 5 GiB guest RAM. The test checks that the old 30% budget would have blocked SenseVoice, then feeds audio at its original pace through the recording manifest and measures the first text, each language's first final, and completion after Stop. Physical latency, acoustic accuracy, mixed-language behavior within a sentence, screen-off capture and WASAPI contention remain **BLOCKED** in #18.
