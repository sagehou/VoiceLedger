# Local transcription

Download a model in **Models**. On Android, enable **Live transcription** and choose Whisper Tiny, SenseVoice Small (ONNX, GGUF Q8_0 or GGUF Q6_K), or Nemotron 3.5 Streaming (GGUF Q4_K_M). Select **Auto** for Mandarin, English and Japanese recognition per speech window. Windows live transcription uses Whisper Tiny. Recording-only is the default. The same models screen can transcribe saved audio. [Issue #10](https://github.com/sagehou/VoiceLedger/issues/10)

The worker reads committed Opus segments while the recorder is running. Both clients aim to seal about two seconds of PCM per segment. The worker finalizes complete speech windows before previewing the unfinished window. With sufficient speech and resources, the first committed segment can yield text. Partials appear separately from the latest eight saved lines. On Windows, each line keeps its microphone or System loopback label. Android binds the isolated worker from the microphone service and shows when it is finishing transcription after Stop. The Android drain watchdog waits 45 seconds between new final revisions. If a worker is suspended or interrupted, choose the same model and language in Sessions to resume from each track's durable progress.

The app refreshes the device profile before starting a task. The shared installer checks the memory and storage reserves, resumes partial HTTPS downloads and verifies the pinned SHA-256 and size of every artifact before probing runtime loadability. Whisper Tiny uses the upstream family memory estimate. SenseVoice uses a provisional 1.1 GB peak RAM estimate based on the Android speech worker measurement. [Catalog](MODEL-CATALOG.md)

The Windows worker process and Android private speech service run inference at reduced priority. One worker per local profile can load a model. A read-only SQLite connection retrieves one committed Opus chunk at a time and validates its checksum. The recorder keeps its separate writer. WebRTC VAD receives transient 16 kHz mono frames. A change of track, source epoch or continuity ends the current speech window. Windows Mic and System loopback keep separate results and share the same loaded model.

Each speech window reuses one utterance ID for ephemeral updates. Only final text enters the local transcript database. Final revisions carry the track, session-relative range, contributing chunk spans, language and model version, runtime version and weight digest. Retrying the same model and language keeps the existing final. A different run for the same range can add a revision and leaves the selected revision in place. Windows sends partials through a same-user pipe and Android uses a private bound service.

Nemotron uses transcribe.cpp's cache-aware stream on the Android microphone track. The worker feeds new committed samples to the same decoder up to a VAD boundary, Gap, pause, or Stop. It uses the model's 1,040 ms right context. Partial text can appear before a language tag is available. The model's locale tag determines the saved language in Auto. An untagged or unsupported result leaves the original audio available for reprocessing. Nemotron initially budgets 1.2 GB for the 496 MB weights and CPU workspace. Q6_K initially uses the same 650 MB estimate as Q8_0. These estimates are provisional until measured.

GitHub Actions builds both pinned native engines, checks version and missing-model behavior on hosted desktops, and packages the Windows x64 and Android arm64 adapters. Model-free checks cover the VAD and transcript paths, the worker boundaries and the packaged manifest. Physical inference, language and mixed-language accuracy, RTF, RAM, and capture under model failure or pressure are **BLOCKED** until the #18 device campaign. [Issue #18](https://github.com/sagehou/VoiceLedger/issues/18)

The Auto regression runs both packaged adapters with pinned weights and the runner disconnected from the network. Kokoro INT8, eSpeak NG and Open JTalk generate two utterances each in Mandarin, English and Japanese. The reports include each detected language, CER or WER, inference latency, RTF, cold load time, process peak RSS and fixture SHA-256. SenseVoice produced fewer Mandarin and Japanese errors in the comparison. Whisper produced fewer English errors. Shortening Whisper's encoder context increased Japanese CER on this corpus, so the packaged decoder retains its existing settings. [Comparison](https://github.com/sagehou/VoiceLedger/actions/runs/45725041896)


The hosted live test checks final text while capture is active, English-only translation, loopback track attribution, final audio drain, and resumption after a low-memory event. The API 35 emulator installs the ARM64 APK and verifies the pinned model downloads. It runs Nemotron Q4_K_M and SenseVoice Q8_0 and Q6_K offline in fresh speech processes. All models receive the same six clips at their original pace. The instrumentation checks that capture commits without loss and measures first visible text on the Compose screen. The report `android-asr-comparison.json` includes process peak RSS, Mandarin and Japanese CER, English WER, and per-language Auto detection. Physical latency, acoustic accuracy, mixed-language behavior within a sentence, screen-off capture and WASAPI contention remain **BLOCKED** in #18.
