# AI scheduling and resource pressure

Windows and Android sample available RAM, low-memory state, free storage, battery and power saver while the speech worker runs. Android also supplies its thermal status when available. The worker evaluates these signals alongside pending jobs, recording state and the measured time spent on each inference window. Windows thermal status remains unknown. [Issue #11](https://github.com/sagehou/VoiceLedger/issues/11)

The recorder keeps its own writer and can run without an AI worker. Power saving defers translation and speaker work first. Backlog or a slow inference window increases the partial interval from three to six seconds. Active capture defers saved-session inference. Live ASR reads committed audio from the selected session. Moderate thermal pressure or low storage defers either ASR mode. A low-memory signal, severe heat or critically low battery stops the worker at the next cancellation point and releases the model. The controller allows one recovery step after ten continuous seconds below the current pressure level. Explicit retries refresh device readings before starting. [AI runtime spec](../spec/06-AI-MODELS-AND-ADAPTIVE-RUNTIME.md)

Job records use the existing local transcript database. A transaction migrates older stores to include the queue. The queue gives VAD and ASR priority over speaker and translation records. The current speech worker executes VAD and ASR together. Live translation uses the same job states and runs one selected English final at a time after available ASR audio is processed. Translation preflight checks memory for both models.

Each speech job keeps the model revision, file digests, language policy and the committed chunk bounds for each source track. A final revision and its checkpoint commit together. Live sessions checkpoint each track independently. A retry with the same model and language resumes from those checkpoints. It skips completed tracks and continues inside a partially processed chunk. If a worker exits while a job is running, the next worker recovers it as deferred. The screen reports the interruption and keeps completed text available. There is no automatic model upgrade during recording.

Actions exercises the queue migration, restart, checkpoint, synthetic resource pressure, monotonic recovery and native resource sampling. Physical recording under sustained AI and resource pressure remains **BLOCKED** for the #18 device campaign. [Issue #18](https://github.com/sagehou/VoiceLedger/issues/18)
