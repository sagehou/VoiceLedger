# Shared domain contract v1

The [JSON Schema](../../contracts/domain-v1.schema.json) defines the wire shape and the [Rust core](../../core/src/contracts/mod.rs) validates state and cross-record rules. A batch carries `schema_version: 1` and each named collection. Empty collections use `[]`. The schema also exposes each entity under `$defs`. Readers reject an unsupported version and unknown fields. Change the version when introducing a different wire shape.

Adapters create lowercase UUIDv4 identities with platform randomness. Record IDs are unique across a batch and survive retry, revision and sync. An utterance ID, translation ID or session-local speaker ID groups records, each of which retains its own record ID. The batch includes the local rows needed to resolve capture, revision, job and benchmark references. A sync journal can reference objects or tombstones outside the batch.

Counts, sequence numbers and timestamps use nonnegative signed 64-bit JSON integers. UTC fields end in `_unix_ms`. Capture uses session-relative monotonic nanoseconds, including the ranges `[start_ns, end_ns)`. Unknown optional measurements use `null` or omission. Source epochs and revision numbers use unsigned 32-bit integers. Revisions start at one.

| Entity | v1 semantics |
| --- | --- |
| Session | Device, title, wall-clock metadata, language policy, optional translation language and separate capture, AI and sync states. Replay the timestamped transitions from Idle. Stop is idempotent. |
| Track | One selected Mic or System loopback endpoint per source in a session. Replay transitions from Preparing. Disconnected tracks retain their identity. A user-confirmed reconnect to the same endpoint advances the source epoch. Recording sessions require at least one recording track. |
| AudioChunk | Stable track, epoch, increasing sequence, range and original format metadata. File bytes and SHA-256 are required for `committed`. Saved availability derives from commit state and those commit facts. |
| Gap and Silence | A Gap represents missing or unknown capture with a cause and recoverability. Silence records a known interval without stored samples. The ranges are disjoint on a track. A missing chunk may retain its manifest alongside a Gap covering the loss. |
| UtteranceRevision | Partial output can travel within a transient batch. Final and manual revisions are durable. Revisions retain their track and source chunk spans. Parent IDs preserve branches. An explicit selection identifies the active durable revision. A machine rerun remains a candidate when a manual revision exists. |
| TranslationRevision | Binds to the exact stable utterance revision. Compare that ID with the selected source to determine staleness. Retain manual translations and give them precedence over machine reruns. |
| SpeakerAssignment and SpeakerProfile | Assignments refer to a session-local speaker and time interval. Confirmed names and profiles require manual provenance. Profiles record consent and opaque encrypted sample and embedding references. |
| AiJob | Stable session, model versions and input ranges or utterance revisions. Audio inputs require committed history. Queued and running audio jobs require the chunk to remain saved. Historical jobs and text can survive local audio loss. |
| DeviceCapabilityProfile and BenchmarkResult | Normalize local hardware observations. Distinguish estimates from measured stages. Measured results include corpus digest, duration and evidence reference. |
| SyncEvent | Immutable per-device journal entry with sequence, entity, operation, revision and encrypted object IDs. A known partial revision or pending audio update fails validation. The encryption envelope and provider protocol are defined by their own milestones. |

During capture, the write adapter supplies commit evidence only after the file and manifest commit. Updating AI or sync states does not change audio durability. Track sequence and range checks apply independently for each source. Each audio, Gap or Silence range stays within the source epoch established by its track's transition times. File reconciliation and physical endpoint handling are covered by the recording and recovery milestones.

The [`contracts` job](CI.md) checks all schema outcomes and generates JSON cases from the [base fixture](../../contracts/fixtures/domain-v1.json) and [case overrides](../../contracts/fixtures/domain-v1-cases.json). Both clients consume the generated bytes through [ABI v1](SHARED-CORE-ABI-V1.md), verify each SHA-256, and assert the common result codes. All fixture data is synthetic.
